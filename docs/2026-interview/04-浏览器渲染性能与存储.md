# 浏览器渲染、性能与存储

> 性能题要回答“如何测量、如何定位、如何验证效果”，而不只是罗列优化手段。

## P0：从 JavaScript 修改状态到页面展示，浏览器经历了什么？

### 30 秒回答

浏览器根据 DOM 和 CSSOM 计算渲染树与样式，必要时进行布局，随后绘制并合成图层显示。修改不同属性的成本不同：影响几何尺寸或位置可能触发布局，视觉样式通常触发绘制，`transform` 和 `opacity` 在合适条件下可主要由合成阶段处理。实际优化要用性能面板验证，不能把“不会回流”当成绝对结论。

### 展开说明

常见问题不是单次布局，而是读写交错造成强制同步布局。例如先写 `style.width`，马上读取 `offsetWidth`，浏览器可能不得不提前刷新布局。应先集中读取，再集中写入，或批量到下一帧处理。

```js
const box = document.querySelector('.box')

// 先读取，再写入，减少读写交错
const width = box.getBoundingClientRect().width
requestAnimationFrame(() => {
  box.style.transform = `translateX(${width}px)`
})
```

### 项目表达

列表滚动卡顿时，我先在 Performance 面板确认瓶颈：是脚本长任务、样式计算、布局、绘制还是图片解码。长列表优先虚拟化；频繁视觉更新优先合帧；图片问题再处理尺寸、格式与懒加载。

### 可能追问

- `display: none` 和 `visibility: hidden` 的差异？前者不参与布局，后者保留布局空间；两者的渲染影响不能只用“回流/重绘”一句概括，需看变化前后和元素上下文。
- `transform` 一定性能更好吗？不一定。滥用图层提升会占用显存，仍需性能测量。

## P0：Core Web Vitals 是什么，如何用于性能优化？

### 30 秒回答

Core Web Vitals 关注用户体验：LCP 衡量主要内容何时呈现，INP 衡量交互到下一次绘制的响应性，CLS 衡量非预期布局位移。优化前先采集真实用户数据和实验室数据，再定位关键资源、长任务和布局位移来源，优化后用同一指标验证。

### 展开说明

LCP 常受首屏关键图片、服务端响应、阻塞资源影响；INP 常受长 JavaScript 任务和同步布局影响；CLS 常来自未预留尺寸的图片、字体切换和异步插入的内容。

```js
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (entry.duration > 50) {
      console.log('long task', entry.startTime, entry.duration)
    }
  }
})

observer.observe({ type: 'longtask', buffered: true })
```

这段代码可帮助发现阻塞主线程超过 50ms 的任务，但它不是完整的指标采集方案；生产环境还需要采样、上报、脱敏和版本维度。

### 项目表达

我会把“首屏慢”拆成可验证目标，例如 LCP、接口时延、关键资源大小和长任务数量。优化可能包括压缩或预加载首屏资源、按路由分包、服务端缓存和减少首屏同步计算。每项改动都保留前后数据，而不是只凭主观感受。

### 可能追问

- 为什么不用 FID？FID 已被 INP 替代，INP 覆盖整个页面生命周期中的交互响应。
- Lighthouse 分数就是线上体验吗？不是。Lighthouse 是受控环境的实验室数据，线上还需 RUM 数据观察真实设备和网络。

## P0：前端存储如何选择？

### 30 秒回答

Cookie 用于服务端需要随请求携带的小型状态，注意 `HttpOnly`、`Secure`、`SameSite` 等属性；`localStorage` 适合少量、长期、非敏感的同步字符串数据；`sessionStorage` 限于当前标签页会话；IndexedDB 适合较大、结构化且需要异步读写的客户端数据。敏感令牌不能因为“方便”就放进可被脚本读取的存储。

### 展开说明

选择时看四件事：数据是否要随请求发送、生命周期、容量与读写方式、安全边界。`localStorage` 是同步 API，大量读写会阻塞主线程；Cookie 会增加每个相关请求的头部开销。

```js
const preferences = {
  theme: 'dark',
  updatedAt: Date.now(),
}

localStorage.setItem('preferences', JSON.stringify(preferences))

const saved = JSON.parse(localStorage.getItem('preferences') ?? 'null')
```

### 项目表达

我会把“登录态”和“UI 偏好”分开设计。登录方案由后端安全模型决定，例如 HttpOnly Cookie 能降低 XSS 直接读取令牌的风险，但仍需要 CSRF 防护；主题、表格列宽等非敏感偏好才适合本地持久化。

### 可能追问

- 浏览器无痕模式下能否依赖存储？不可假定容量和持久性，必须处理写入失败和降级。
- IndexedDB 适合替代服务端数据库吗？不适合，它是本地缓存或离线能力的一部分，仍要考虑同步和数据一致性。

## P1：如何排查页面内存持续增长？

### 30 秒回答

先稳定复现操作路径，使用 Chrome Performance Monitor 观察 JS heap、DOM 节点和监听器趋势，再用 Heap Snapshot 或 Allocation Instrumentation 对比引用链。重点排查未销毁的组件、全局缓存、定时器、事件监听、第三方实例和 Detached DOM。

```js
function createPolling(callback) {
  const timer = window.setInterval(callback, 5_000)
  return () => window.clearInterval(timer)
}

const stopPolling = createPolling(loadData)
// 组件卸载或页面离开时调用
stopPolling()
```

### 项目表达

我会先证明是泄漏而非正常缓存：重复进入退出页面后，强制 GC 后堆大小仍持续抬升，才进一步看快照中谁保留了对象。修复后重复同一操作，并对比修复前后的快照和监控曲线。

## P1：资源加载怎么做取舍？

### 30 秒回答

首屏关键资源优先、非关键资源延后。图片明确尺寸以避免 CLS，根据场景使用现代格式、响应式图片和懒加载；脚本通过路由或组件分包，谨慎使用 `preload`，避免所有资源都抢占带宽。

### 可能追问

- `preload` 和 `prefetch` 的差别？前者用于当前页面很快会使用的高优先级资源，后者通常用于未来导航的低优先级预取；二者都应以实际需求为准。
