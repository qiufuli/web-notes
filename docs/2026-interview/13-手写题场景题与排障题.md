# 手写题、场景题与排障题

> 手写题的目的不是在生产里重复造轮子，而是考察基础、边界意识和表达过程。写出正确的最小版本后，要主动说明生产环境会使用成熟方案并补充测试。

## P0：如何实现防抖和节流？怎样选择？

### 30 秒回答

防抖是在连续触发结束一段时间后才执行，适合搜索输入、窗口尺寸计算；节流是在一段时间内最多执行一次，适合滚动、拖拽和高频上报。实现时要考虑 `this`、参数、取消、首次/末次执行以及组件卸载清理。

```ts
type Debounced<T extends (...args: any[]) => void> = ((
  this: ThisParameterType<T>,
  ...args: Parameters<T>
) => void) & {
  cancel: () => void
}

export function debounce<T extends (...args: any[]) => void>(fn: T, wait: number) {
  let timer: ReturnType<typeof setTimeout> | undefined

  const debounced = function (this: ThisParameterType<T>, ...args: Parameters<T>) {
    if (timer) clearTimeout(timer)
    timer = setTimeout(() => {
      timer = undefined
      fn.apply(this, args)
    }, wait)
  } as Debounced<T>

  debounced.cancel = () => {
    if (timer) clearTimeout(timer)
    timer = undefined
  }

  return debounced
}
```

```ts
export function throttle<T extends (...args: any[]) => void>(fn: T, wait: number) {
  let lastTime = 0
  let timer: ReturnType<typeof setTimeout> | undefined

  return function throttled(this: ThisParameterType<T>, ...args: Parameters<T>) {
    const now = Date.now()
    const remaining = wait - (now - lastTime)

    if (remaining <= 0) {
      if (timer) clearTimeout(timer)
      timer = undefined
      lastTime = now
      fn.apply(this, args)
      return
    }

    if (!timer) {
      timer = setTimeout(() => {
        lastTime = Date.now()
        timer = undefined
        fn.apply(this, args)
      }, remaining)
    }
  }
}
```

### 展开说明

上面的节流保留首次和末次调用。面试时应主动说清这一策略；不同产品需求可能只要首次、只要末次或需要提供 `cancel/flush`。实际项目优先使用经过验证的工具库，除非需要特殊行为。

### 项目表达

搜索框常用防抖，但仍需在请求层处理取消和竞态；滚动位置更新可节流或使用 `requestAnimationFrame`。组件销毁时必须取消尚未执行的定时器，避免更新已卸载页面。

## P0：深拷贝有哪些边界？为什么不建议只用 JSON？

### 30 秒回答

深拷贝不是总需要，优先使用不可变更新或明确的数据结构。`JSON.stringify/parse` 会丢失 `undefined`、函数、Symbol、循环引用，并不能正确处理 Date、Map、Set 等。现代环境可优先使用 `structuredClone`，但它也不能克隆函数、DOM 节点等；复杂业务模型通常应通过序列化协议或领域转换明确处理。

```ts
const source = {
  createdAt: new Date(),
  tags: new Set(['vue', 'ts']),
}

const copied = structuredClone(source)
copied.createdAt instanceof Date // true
copied.tags instanceof Set // true
```

### 项目表达

状态管理中我不会为了“防止引用”每次都深拷贝整个对象。先定位真正需要隔离的边界，例如提交表单前生成 payload、编辑草稿与原始数据分离；大型数据的无差别深拷贝会增加性能和内存开销。

### 可能追问

- 手写深拷贝要处理什么？循环引用、Date、RegExp、Map/Set、Symbol key、原型和属性描述符等；面试时应先明确题目范围。
- 浅拷贝有什么问题？只复制第一层，嵌套对象仍共享引用。

## P0：如何实现受控并发请求？

### 30 秒回答

批量任务不能直接无限 `Promise.all`。实现一个任务池，限制同时执行数量，任务完成后再取下一个；同时定义失败策略、取消、进度和结果顺序。并发数取决于文件大小、接口限流和用户网络，不应迷信固定值。

```ts
export async function runWithLimit<T, R>(
  items: T[],
  limit: number,
  worker: (item: T) => Promise<R>,
) {
  const results = new Array<R>(items.length)
  let cursor = 0

  async function consume() {
    while (cursor < items.length) {
      const index = cursor++
      results[index] = await worker(items[index])
    }
  }

  await Promise.all(Array.from({ length: Math.min(limit, items.length) }, consume))
  return results
}
```

### 可能追问

- 一个任务失败怎么办？由需求决定 fail-fast、继续收集错误或重试；不要默认吞掉失败。
- `limit` 为 0 怎么办？生产实现要参数校验，此处为了展示核心调度逻辑省略。

## P0：遇到线上白屏，如何排查？

### 30 秒回答

先判断影响范围和版本，优先止损，再分层定位：HTML 是否返回、静态资源是否 404 或缓存错配、JavaScript 是否在启动时报错、接口或权限是否失败、路由是否匹配、运行环境是否有兼容问题。结合错误监控、网络瀑布、用户信息和发布记录，而不是一开始就改代码。

### 排查路径

1. 确认是全量还是特定浏览器、路由、租户或用户角色。
2. 查看最近发布、构建版本、CDN 与 HTML 入口是否一致。
3. 查看控制台错误、资源状态码、Source Map 还原的堆栈。
4. 区分启动异常、异步数据失败、权限跳转循环和渲染卡死。
5. 通过开关、回滚、降级页或修复补丁止损。
6. 复现后补回归用例、监控告警和发布检查项。

### 项目表达

对线上事故，我会先给出影响范围、当前状态、止损动作和下一次同步时间。技术排查要保留时间线，避免多人同时猜测导致信息混乱。

## P1：接口很慢或偶发失败，如何排查？

### 30 秒回答

先用请求 ID、状态码、耗时分段和发生比例确定问题位置：DNS/TLS/连接、网关、服务端处理、数据库或前端重复请求。前端可做超时、取消、重试和降级，但不能用无限重试掩盖后端故障。

### 可能追问

- 什么请求可以重试？幂等、可安全重放的请求可考虑指数退避重试；创建订单、支付等写操作必须由服务端幂等键和业务语义保障。
- 如何避免重复提交？按钮状态只是体验层，前端可生成请求标识，最终由服务端幂等控制。

## P1：如何定位内存泄漏或性能回退？

### 30 秒回答

稳定复现操作路径，先用浏览器 Performance/Memory 工具证实趋势，再查看长任务、堆快照、Detached DOM、监听器、定时器和缓存引用。性能回退也要用基线对比，区分网络、脚本、布局、绘制和接口问题。

### 项目表达

修复后要重复相同操作并对比快照或指标，而不是只看一次“感觉不卡了”。对于大列表和复杂图表，优先审查卸载、数据保留和组件更新边界。
