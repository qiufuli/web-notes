# ES6 高频特性：不是背语法，而是建立 JavaScript 的使用边界

> “ES6 有哪些特性”范围很大。面试真正高频的不是把清单念完，而是你能不能解释：变量为什么会串、`this` 为什么丢、异步为什么难写、对象为什么改着改着影响了别处，以及模块为什么能做 Tree Shaking。

## 一、先建立主线：ES6 在改善什么

ES6 不是一组零散糖衣，它主要改善了几类老问题：

```text
变量边界不清       -> let / const、块级作用域
函数上下文容易丢失 -> 箭头函数、默认参数、rest
异步回调难组合     -> Promise、async / await
集合和对象表达不足 -> Set、Map、解构、Proxy
文件依赖难管理     -> ESM、动态 import
```

下面按“问题 -> 机制 -> 边界”理解，而不是孤立背 API。

## 二、`var` 为什么容易出问题，`let`/`const` 改了什么

### 1. 问题：循环回调共享了同一个变量

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0)
}
// 3, 3, 3
```

`var` 是函数作用域。循环结束时 `i` 已经是 3，三个回调读到的是同一个变量。

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0)
}
// 0, 1, 2
```

`let` 是块级作用域，并且循环每轮有独立绑定，因此每个回调各自记住当轮的 `i`。

### 2. `const` 不等于对象不可变

```js
const user = { name: '张三' }
user.name = '李四' // 合法
// user = {}      // 报错：不能重新绑定
```

`const` 约束的是变量绑定不能重新指向另一个值，并不冻结对象内容。需要真正不可变时，应创建新对象或使用明确的冻结/状态管理策略。

### 3. 暂时性死区的意义

`let`、`const` 在声明前不能访问：

```js
console.log(count) // ReferenceError
let count = 1
```

这能更早暴露“在初始化前使用变量”的错误。说“let 不提升”并不严谨；更准确是它也有声明提升的语义，但在声明执行前处于暂时性死区，不能读取。

## 三、解构、默认值与展开：方便不等于深拷贝

```js
const { name = '匿名', id, ...rest } = { id: 1 }
const nextUser = { ...user, name: '李四' }
```

默认值只在值是 `undefined` 时生效，不会覆盖 `null`、`0`、空字符串：

```js
const { page = 1 } = { page: null } // page 是 null
```

对象展开和 `Object.assign` 都是**浅拷贝**：

```js
const a = { profile: { city: '长春' } }
const b = { ...a }
b.profile.city = '北京'
console.log(a.profile.city) // 北京
```

因为内层对象仍是同一个引用。面试中能主动说出“浅拷贝边界”，比只会写 `{ ...obj }` 更有分量。

## 四、箭头函数到底改变了什么：`this` 从哪里来

普通函数的 `this` 由**调用方式**决定：

```js
const user = {
  name: '小王',
  say() { return this.name },
}
user.say() // this 是 user
```

箭头函数没有自己的 `this`，它在定义时从外层词法作用域捕获：

```js
class Timer {
  count = 0
  start() {
    setInterval(() => {
      this.count++ // 箭头函数沿用 start 的 this
    }, 1000)
  }
}
```

这就是它适合回调的原因。但它不适合需要动态 `this` 的对象方法：

```js
const user = {
  name: '小王',
  say: () => this.name,
}
```

这里的 `this` 不会指向 `user`。此外箭头函数没有自己的 `arguments`、不能用作构造函数，也没有 `prototype`。结论不是“都用箭头函数”，而是：**需要词法 this 的回调用箭头函数；需要调用方决定 this 的方法用普通函数。**

## 五、Promise 和 async/await：把“未来的结果”变成可组合的值

### 1. 为什么回调会难维护

多步骤异步流程若层层嵌套，成功、失败、重试和并发关系很难读：

```js
loadUser(id, user => {
  loadOrders(user.id, orders => {
    // 继续嵌套
  })
})
```

Promise 将“未来会成功或失败的结果”抽象成对象。它有 pending、fulfilled、rejected 三种状态；状态一旦落定就不会再变。

```js
getUser(id)
  .then(user => getOrders(user.id))
  .then(orders => render(orders))
  .catch(showError)
```

`then` 返回新的 Promise，因此返回值、抛错或另一个 Promise 都能继续沿链传递。`throw` 等价于让后续链进入拒绝状态。

### 2. `async/await` 没有让异步变同步

```js
async function loadPage() {
  const user = await getUser(1)
  return user.name
}
```

`async` 函数总返回 Promise；`await` 暂停的是当前 async 函数的后半段，不会堵住 JavaScript 主执行路径。异常可以用 `try/catch` 处理：

```js
try {
  const user = await getUser(1)
} catch (error) {
  showError(error)
}
```

### 3. 串行和并发要主动选择

互不依赖的请求写成两个 `await` 会无意间串行：

```js
const users = await getUsers()
const roles = await getRoles()
```

可并发时先创建 Promise，再一起等待：

```js
const [users, roles] = await Promise.all([getUsers(), getRoles()])
```

`Promise.all` 任一失败就整体失败；希望收集每个结果时用 `Promise.allSettled`。`Promise.race` 是最先 settled 的结果，`Promise.any` 是最先成功的结果。取消请求不是 Promise 自带能力，前端通常要配合 `AbortController` 或业务版本号处理。

## 六、Set、Map 和迭代：什么时候不该继续用对象和数组

```js
const selectedIds = new Set([1, 2])
selectedIds.add(3)

const cache = new Map()
const element = document.querySelector('#app')
cache.set(element, { mountedAt: Date.now() })
```

- `Set` 表示唯一值集合，适合去重和集合运算思维。
- `Map` 的键可以是任意值，天然有 `size`、迭代顺序和 `has` 语义；对象字面量则更适合固定字段结构。

`for...of` 消费可迭代对象，例如数组、Set、Map、字符串：

```js
for (const [key, value] of cache) {
  console.log(key, value)
}
```

它和 `for...in` 不同：`for...in` 枚举可枚举属性名，可能遍历到原型链，不适合常规数组遍历。

## 七、ESM 为什么能帮助工程化

```js
// math.js
export function add(a, b) { return a + b }
export function unusedDebug() { /* ... */ }

// app.js
import { add } from './math.js'
```

ES Module 的 `import/export` 是静态结构：构建工具能在构建时知道依赖了哪个导出，因此有机会删除未使用的 `unusedDebug`。这就是 Tree Shaking 的基础。

它不是绝对保证：CommonJS 的动态导出、模块顶层副作用、错误的 `sideEffects` 配置，都会让构建工具无法安全删除代码。

动态 `import()` 返回 Promise，适合路由和低频功能按需加载：

```js
const { openEditor } = await import('./editor.js')
openEditor()
```

## 八、面试官想听到的话

### 30 秒版本

> ES6 我会按解决的问题理解。`let/const` 提供块级作用域，`const` 只限制重新绑定；解构和展开便于处理数据，但对象展开是浅拷贝。箭头函数没有自己的 this，适合保留外层上下文的回调，不适合所有对象方法。Promise 和 async/await 让异步结果能链式组合，互不依赖的请求会用 `Promise.all` 并发。Set/Map 分别适合唯一集合和任意键映射。ESM 的静态 import/export 为 Tree Shaking 提供了前提，动态 import 用于按需加载。

### 追问时的答题顺序

先讲“它解决的旧问题”，再说最小机制，最后主动补一个边界。例如讲箭头函数时，说词法 this，再补“不能当构造函数，也不适合作为依赖动态 this 的对象方法”。这样比背定义更像真正使用过。

