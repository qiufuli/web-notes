# 跨章节串讲与项目场景

> 资深面试很少只问一个 API。面试官往往从一个项目场景连续追问：状态放哪里、请求怎么取消、权限怎么控制、类型怎么建模、发布怎么回滚。下面按真实场景把各章串起来。

## P0：设计一个后台管理系统的权限体系

### 30 秒回答

权限至少分为认证、路由权限、页面元素权限和服务端资源授权四层。登录态和权限信息由后端提供，Pinia 保存当前会话状态；路由守卫控制页面进入，按钮或组件控制操作入口，服务端最终校验资源归属。刷新时恢复权限，退出或租户切换时清理旧状态，不能把前端隐藏按钮当成安全措施。

### 展开思路

1. **认证**：Cookie 或 Token 的生命周期、刷新、失效和退出。
2. **路由**：公开路由、登录重定向、动态路由、404 和导航循环。
3. **菜单与按钮**：后端权限标识映射到稳定的前端能力，不把任意字符串直接当组件路径。
4. **接口授权**：每次请求由服务端校验身份、角色、租户和资源归属。
5. **状态清理**：退出时清理 Pinia、缓存、WebSocket、定时器和页面敏感数据。

### 会被追问什么

- 刷新页面后 Pinia 没了怎么办？使用安全的恢复流程重新拉取用户信息，不要无脑把完整用户对象放 localStorage。
- 权限变化后如何处理已打开页面？路由和接口都应重新校验，必要时清理动态路由并跳转无权限页。
- 前端按钮权限能防止越权吗？不能，服务端必须再次授权。

## P0：实现一个可取消、可重试的列表页

### 30 秒回答

把筛选条件、分页、loading、data、error 和请求控制器作为一个明确的页面状态模型；输入搜索使用防抖，发起新请求前取消旧请求，并用请求序号或当前查询条件校验结果。查询类请求可以有限重试，写操作不能只依赖前端重试。

```ts
type ListState<T> =
  | { status: 'idle'; data: T[] }
  | { status: 'loading'; data: T[] }
  | { status: 'success'; data: T[] }
  | { status: 'error'; data: T[]; message: string }

let controller: AbortController | undefined
let version = 0

async function loadList(query: string) {
  controller?.abort()
  controller = new AbortController()
  const currentVersion = ++version

  const response = await fetch(`/api/list?q=${encodeURIComponent(query)}`, {
    signal: controller.signal,
  })
  const data = await response.json()

  if (currentVersion !== version) return
  return data
}
```

### 会被追问什么

- 为什么取消后还要校验版本？取消和响应到达可能存在竞态，版本校验是最后一道状态保护。
- 筛选条件放 Store 吗？需要分享或跨页面恢复可放 query；只属于一个列表页通常留在 composable 或组件。
- 表格数据需要 Pinia 吗？看复用范围和缓存失效，不要因“列表很重要”就全局化。

## P0：封装一个复杂表单组件

### 30 秒回答

先定义受控边界：表单值由父组件通过 `v-model` 传入，子组件通过 `update:modelValue` 返回更新；校验规则、错误展示、提交和重置是明确的组件能力。字段模型用 TypeScript 描述，异步校验支持取消，组件卸载时清理监听和请求，不把页面 Store 直接暴露给基础组件。

### 设计要点

- 基础输入组件负责展示和事件，不负责业务请求。
- 表单容器负责字段注册、校验顺序、错误聚焦和提交状态。
- 页面负责调用接口、处理成功跳转和服务端错误。
- `aria-invalid`、错误描述、键盘焦点和移动端输入都纳入验收。

### 会被追问什么

- 子组件如何修改父组件的表单值？emit 更新事件，不直接改 prop。
- 服务端返回字段错误怎么办？把后端字段路径映射到表单模型，未知错误保留为表单级错误。
- 组件过于通用怎么办？拆分基础输入、业务表单和页面编排，减少布尔 prop 爆炸。

## P1：大表格或大列表卡顿如何定位和优化？

### 30 秒回答

先用 Performance 和 Vue Devtools 确认是数据量、组件更新、脚本长任务、布局还是绘制问题。大数据量优先分页、虚拟列表和服务端筛选；组件层稳定 props、减少深度响应式和昂贵 computed；渲染层固定尺寸、避免读写交错；图片和导出等重计算可考虑 Worker。

### 会被追问什么

- 为什么不能只用 `v-memo`？它只能跳过明确稳定的子树，不能解决数据传输、布局和绘制成本。
- 虚拟列表有什么代价？需要估算或测量行高，滚动定位、键盘操作和可访问性实现更复杂。
- 如何证明优化有效？对比同一设备、数据量、操作路径下的长任务、INP、内存和帧率。

## P1：文件上传、下载和大文件场景怎么设计？

### 30 秒回答

上传要考虑大小限制、类型校验、进度、取消、重试、断点续传和服务端最终校验；下载要区分浏览器展示、直接下载和鉴权资源，不能把大文件完整读进内存。大文件可切片上传，服务端用文件 hash、分片编号和幂等机制合并。

### 会被追问什么

- 前端校验能安全吗？不能，前端校验只是体验，服务端仍需校验内容、权限和病毒风险。
- 断点续传如何避免重复分片？用文件 hash 和分片编号作为幂等键，服务端返回已上传分片。

## P0：发布后出现 chunk load error 或白屏怎么办？

### 30 秒回答

先确认影响范围、版本和资源状态码，检查 HTML 是否指向新版本而旧 chunk 已被删除、CDN 是否缓存不一致、Service Worker 是否持有旧资源。先通过保留旧资源、回滚 HTML 或降级入口止损，再修复资源保留和缓存策略，避免无限刷新。

### 排查顺序

1. 错误监控确认错误版本、路由和资源 URL。
2. 网络面板确认 chunk 是 404、超时、CORS 还是解析错误。
3. 检查部署是否原子切换，旧 hash 资源是否过早删除。
4. 检查 HTML、CDN、Service Worker 和浏览器缓存版本。
5. 发布兼容修复，保留一段时间旧资源并补自动化检查。

## P1：如何把一个线上问题讲成资深工程师的答案？

### 30 秒回答

按“影响范围、止损动作、证据、根因、修复、验证、复盘”讲，不要只说最后改了哪一行代码。资深回答要体现优先级和协作：先降低用户影响，再让定位过程可复查，最后把修复沉淀为测试、监控或流程改进。

### 自检清单

- 是否先确认事实，而不是直接猜原因？
- 是否说清自己负责的部分和协作边界？
- 是否说明为什么选这个方案、放弃了什么方案？
- 是否有修复后的验证方式？
- 是否避免虚构没有实际做过的指标和职责？
