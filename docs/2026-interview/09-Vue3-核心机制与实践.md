# Vue 3 核心机制与实践

> Vue 3 不只是把 `data` 改成 `ref`。它把状态、派生值、副作用、组件 API 和逻辑复用放到更显式的组合式模型中。学习时要一直追问：状态由谁拥有，谁读取它，谁负责清理它？

## 一、先建立 Vue 3 的工作模型

```text
状态（ref/reactive）
  -> 模板、computed 或 watch 读取并收集依赖
状态变化
  -> trigger 相关 effect
  -> 调度组件更新或副作用
  -> patch DOM / 执行副作用
```

Vue 3 的 API 选择，都可以放回这条主线：`ref` 和 `reactive` 描述状态，`computed` 描述派生值，`watch` 描述副作用，composable 描述可复用的状态逻辑，Pinia 负责应用级共享状态。

## 二、状态为什么有 `ref` 和 `reactive`

### P0：`ref` 和 `reactive` 怎么选？

先看状态的形状，而不是背“基本类型用 ref、对象用 reactive”这句口诀：

```ts
import { reactive, ref, toRefs } from 'vue'

const page = ref(1)                         // 独立值，可整体替换
const query = reactive({ keyword: '', page: 1 }) // 一组有内聚关系的字段

page.value += 1
query.keyword = 'Vue 3'
```

`ref` 用一个带 `.value` 的容器承载依赖，能包装基本值，也方便整体替换对象；`reactive` 返回一个 Proxy，适合对同一对象的字段操作。`reactive` 变量本身不能直接替换为新对象：

```ts
let query = reactive({ keyword: '' })
query = reactive({ keyword: 'new' }) // 变量换了引用，旧引用的消费者不会自动跟随
```

需要解构时要保留连接：

```ts
const state = reactive({ count: 0 })
const { count } = toRefs(state)
count.value++
```

直接 `const { count } = state` 会取出一个普通 number，因为后续读取绕过了 Proxy。

### Vue 3 Proxy 到底改善了什么

Vue 2 是给已知属性安装 getter/setter；Vue 3 代理整个对象，可以拦截新增、删除、数组索引和更多对象操作：

```js
const state = new Proxy({ count: 0 }, {
  get(target, key, receiver) {
    track(target, key)
    return Reflect.get(target, key, receiver)
  },
  set(target, key, value, receiver) {
    const oldValue = target[key]
    const ok = Reflect.set(target, key, value, receiver)
    if (oldValue !== value) trigger(target, key)
    return ok
  },
})
```

这段代码只是思想模型。真实 Vue 还要处理嵌套代理、effect 栈、条件分支清理、调度器和集合类型。正确的核心表达是：**读取时 track，写入时 trigger；按对象和 key 找到相关 effect。**

## 三、computed、watch 和 watchEffect 的边界

### P0：它们为什么不能互相替代

```text
纯派生值，依赖不变时可复用 -> computed
明确监听某个来源并执行副作用 -> watch
简单副作用，自动收集同步依赖 -> watchEffect
```

```ts
const keyword = ref('')
const page = ref(1)

const hasKeyword = computed(() => keyword.value.trim().length > 0)

watch([keyword, page], async ([nextKeyword, nextPage], _old, onCleanup) => {
  const controller = new AbortController()
  onCleanup(() => controller.abort())

  const response = await fetch(`/api/list?q=${nextKeyword}&page=${nextPage}`, {
    signal: controller.signal,
  })
  console.log(await response.json())
})
```

`computed` 的 effect 被依赖变化标记为脏，下次读取时才重新计算，因此有缓存；`watch` 适合请求、日志、写 localStorage、同步第三方系统。异步 watch 必须考虑旧请求返回覆盖新请求，cleanup、AbortController 或请求版本号都可以解决。

`watchEffect` 会立即执行，并自动收集回调中同步访问到的依赖；第一个 `await` 之后才访问的依赖不会自动收集。依赖边界复杂时，显式 `watch` 更容易维护。

## 四、组件 API：为什么 `<script setup>` 不是“没有边界”

### P0：Props、Emits 和 `v-model` 如何设计

父组件拥有状态，子组件通过 props 接收，通过 emits 表达更新意图：

```vue
<script setup lang="ts">
type User = { id: string; name: string }

const props = defineProps<{
  user: User
  disabled?: boolean
}>()

const emit = defineEmits<{
  select: [id: string]
}>()

function handleSelect() {
  if (!props.disabled) emit('select', props.user.id)
}
</script>
```

组件 `v-model` 只是下面两步的组合：

```vue
<SearchBox
  :model-value="keyword"
  @update:model-value="keyword = $event"
/>
```

命名模型 `v-model:visible` 对应 `visible` 与 `update:visible`。不要让子组件直接改 prop；如果需要内部草稿，应明确草稿的初始值、外部变化同步规则和提交时机。

`defineProps`、`defineEmits` 是编译器宏，`<script setup>` 顶层变量可以直接用于模板；这减少了样板代码，但没有取消组件 API 设计。

## 五、生命周期的本质：和外部系统同步并负责清理

### P0：什么时候用生命周期，什么时候不用

生命周期不是“把所有逻辑分散到钩子里”：

```ts
import { onMounted, onUnmounted, ref } from 'vue'

const width = ref(window.innerWidth)

function updateWidth() {
  width.value = window.innerWidth
}

onMounted(() => window.addEventListener('resize', updateWidth))
onUnmounted(() => window.removeEventListener('resize', updateWidth))
```

原则是“谁创建，谁清理”：监听器、定时器、WebSocket、图表实例、请求取消都要有对应清理。`setup` 没有组件实例 `this`，但能在组件生命周期上下文中注册钩子。

## 六、Composable：把一类逻辑抽出来，而不是把页面拆碎

### P0：什么是 composable，怎样避免抽乱

Composable 是围绕一个明确关注点复用状态逻辑的函数，通常提供输入、状态、操作和清理：

```ts
import { onUnmounted, ref } from 'vue'

export function useInterval(callback: () => void, delay = 5000) {
  const active = ref(false)
  let timer: number | undefined

  function start() {
    if (timer !== undefined) return
    timer = window.setInterval(callback, delay)
    active.value = true
  }

  function stop() {
    if (timer === undefined) return
    window.clearInterval(timer)
    timer = undefined
    active.value = false
  }

  onUnmounted(stop)
  return { active, start, stop }
}
```

如果一个 composable 同时处理表单、请求、弹窗、路由、埋点，通常已经超过一个关注点。Composable 默认每次调用拥有独立状态；把状态定义在函数外才会变成共享单例，需要明确说明生命周期。

## 七、浅层响应式、第三方实例与大型数据

### P0：`toRef`、`shallowRef`、`markRaw` 何时使用

- `toRef/toRefs`：从 reactive 对象取出仍然连回源对象的 ref。
- `shallowRef`：只追踪 `.value` 的替换，适合大型不可变数据或第三方实例。
- `markRaw`：告诉 Vue 某个对象不要被代理，适合图表、地图等类实例。

```ts
const chart = shallowRef<ChartInstance | null>(null)

function mountChart(instance: ChartInstance) {
  chart.value = markRaw(instance)
}
```

选这些 API 是因为明确存在代理成本或实例兼容性问题，不是为了“用了高级 API 就更快”。第三方实例还需要在 `onUnmounted` 中调用销毁方法。

## 八、KeepAlive、Teleport 和异步组件放在什么位置

`KeepAlive` 缓存组件实例，切出触发 `onDeactivated`，回来触发 `onActivated`，不代表接口数据永远新鲜；需要在激活时按过期策略刷新。

`Teleport` 解决 DOM 层级问题，例如把弹窗挂到 `body` 避开裁剪，但组件逻辑和响应式归属仍在原组件树中。`Transition` 协调进入/离开阶段的 class 和钩子。异步组件通过 `defineAsyncComponent` 延迟加载低频模块，加载失败、超时和错误态要有业务处理；不是所有首屏组件都应该懒加载。

## 九、Vue 3 性能与 SSR 的判断方式

性能优化先定位更新原因：稳定 props、拆分长列表、虚拟化、减少不必要深层代理、按路由分包。`v-once`、`v-memo` 只适合明确稳定的子树，滥用会导致状态不更新。

SSR 先在服务端生成 HTML，客户端 hydration 接管已有 DOM。服务端和客户端首次渲染不一致时会出现 hydration mismatch，随机数、当前时间、浏览器 API 和登录态差异都是常见来源。

## 十、面试官想听到的话

### 30 秒版本

> Vue 3 响应式可以概括为读时 track、写时 trigger：`reactive` 用 Proxy 代理对象，`ref` 用容器承载基本值或整体可替换的状态。computed 是带缓存的派生值，watch 是明确来源的副作用，watchEffect 是自动收集依赖的简单副作用。组件仍遵循 props 下传、emit 上报，`v-model` 是这两步的语法糖。Composable 用于复用一类状态逻辑，生命周期的重点是和外部系统同步并由创建者负责清理。性能优化和 KeepAlive、异步组件都应基于真实场景与测量决定。

### 2 分钟版本

> 我会先用“状态由谁拥有、谁读取、谁清理”组织 Vue 3。状态被模板或 effect 读取时建立依赖，修改时只触发相关 effect；Proxy 改善了 Vue 2 对新增属性和数组操作的侦测边界，ref 则解决基本值和整体替换。computed 适合纯派生并缓存，watch 适合请求等副作用，异步 watch 要取消旧请求或做版本校验。组件通过类型化 Props/Emits 建立契约，子组件不直接改 prop；composable 围绕单一关注点复用逻辑，并清理监听、定时器和第三方实例。实际项目中我会把页面局部状态、共享状态和服务端数据分开，再用 Devtools 和 Performance 定位性能问题，而不是机械堆 API。
