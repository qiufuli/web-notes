# 模拟面试追问库

> 使用方式：先独立回答主问题，再看追问检查自己的边界、项目细节与表达是否真实。每一题都应能回到你真正做过的系统和职责。

## P0：自我介绍与项目深挖

### 主问题：请介绍一下你自己，以及最有代表性的项目。

### 30 秒回答要点

用技术主线和项目类型定位自己，选择一个亲自深度参与的难题，按背景、职责、决策、验证讲述。Vue 2 存量经验要转化为业务稳定性、治理与协作能力；Vue 3/TypeScript 则说明已经建立的学习和实践路径。

### 追问

1. 你在项目中最难的一个问题是什么，为什么难？
2. 这个方案有哪些替代方案，为什么没有选？
3. 结果如何验证，哪个指标或验收方式能证明有效？
4. 如果重做一次，你会提前做什么？

### 回答检查

- 能区分个人职责与团队成果。
- 不虚构业务规模、性能百分比或管理职责。
- 至少说出一个技术风险和一个业务约束。

## P0：Vue 2 遗留项目治理

### 主问题：你们为什么没有把 Vue 2 项目直接升级到 Vue 3？

### 30 秒回答要点

先承认 Vue 3 的长期价值，再说明迁移需要评估依赖、业务窗口、测试覆盖、团队成本和回滚能力。稳定存量系统优先治理高风险模块、测试和工程链路；新模块或低耦合页面可试点现代栈，避免全量重写。

### 追问

1. Vue 2 响应式的数组和动态属性有哪些边界？
2. 如果要迁移，第一批页面怎么选？
3. Vuex 是否必须替换成 Pinia？
4. 如何证明迁移没有引入回归？

### 回答检查

- 能讲清 Vue 2 的 `Object.defineProperty` 边界。
- 能给出灰度、监控、关键路径测试和回滚等控制手段。
- 不把“新框架”当作迁移的唯一理由。

## P0：Vue 3 与组件设计

### 主问题：Vue 3 中 `ref`、`reactive`、`computed` 和 `watch` 如何选择？

### 30 秒回答要点

先按“状态、派生值、副作用”划分。基本值或整体替换用 `ref`，相关对象字段可用 `reactive`，纯派生值用 `computed`，请求、订阅等副作用用 `watch` 并做清理。说明 reactive 解构和深度监听的边界。

### 追问

1. 搜索输入变化时如何避免旧请求覆盖新请求？
2. 什么逻辑该抽 composable，什么状态该放 Pinia？
3. `<script setup>` 相比 Options API 改善了什么？
4. 子组件为什么不能直接修改 props？

### 回答检查

- 能给出一个真实的页面状态划分。
- 能说出请求取消、竞态或组件卸载清理。

## P0：TypeScript 与业务建模

### 主问题：TypeScript 在 Vue 项目里给你带来什么实际收益？

### 30 秒回答要点

重点说组件 Props/Emits、接口模型、状态机和重构保护。用 `unknown` 接外部输入、用联合类型表达加载状态、用泛型表达请求结果。承认 TypeScript 不替代运行时校验和后端契约。

### 追问

1. `any` 和 `unknown` 的区别？
2. 如何为列表接口和分页参数建模？
3. `type` 与 `interface` 如何选择？
4. 如何渐进给老 Vue 2 项目引入 TypeScript？

### 回答检查

- 不把“加类型”说成只写 interface。
- 能解释接口字段不可信时的校验和兜底。

## P1：Pinia、路由与权限

### 主问题：哪些状态应该放 Pinia？

### 30 秒回答要点

根据共享范围和生命周期划分：组件 UI 状态留在组件，页面复用逻辑放 composable，需要刷新/分享的筛选条件可放 URL，需要跨路由共享的用户、权限、全局配置才放 Pinia。服务端数据需另考虑缓存和失效。

### 追问

1. Pinia 与 Vuex 的区别和迁移判断？
2. 刷新后权限路由如何恢复？
3. 前端权限控制是否足够安全？
4. Store 持久化时有哪些安全和版本问题？

## P1：Vite、性能与发布

### 主问题：Vite 为什么开发快，生产构建又如何保证质量？

### 30 秒回答要点

开发阶段按需提供原生 ESM 并预构建依赖，生产使用 Rollup 打包优化。质量依赖于类型检查、测试、构建版本、错误监控、灰度和回滚，而不是只看构建成功。

### 追问

1. 环境变量为什么不能存密钥？
2. 如何定位首屏慢？
3. Source Map 如何兼顾排障和安全？
4. 前端回滚为什么还要考虑接口兼容？

## P1：协作与问题处理

### 主问题：你如何处理线上问题和多人协作中的分歧？

### 30 秒回答要点

线上先明确影响、止损和同步节奏，再用版本、日志、监控和可复现步骤定位；协作分歧回到目标、约束和证据，明确决策记录与验收标准。资深经验体现在降低团队不确定性，而不是“我说了算”。

### 追问

1. 怎样避免同一类线上问题重复发生？
2. 如何推动规范落地而不是只写文档？
3. 新同事或经验较少的成员卡住时怎样帮助？
4. 你如何判断一个重构值得做？

## 使用建议

每次模拟选择三类题：一个项目题、一个 Vue/TypeScript 题、一个工程或场景题。录音复盘时重点检查：是否先给结论、是否解释边界、是否说清自己的职责、是否有无法被追问支撑的空泛表述。
