# CSS 布局与工程实践

> CSS 面试不需要展示画五角星的熟练度，更重要的是能稳定解决布局、层级、响应式和可访问性问题。

## P0：Flex 和 Grid 如何选择？

### 30 秒回答

Flex 适合一维布局，即主要沿一个方向排列、对齐和分配空间，例如工具栏、表单行和列表项；Grid 适合二维布局，需要同时控制行和列，例如仪表盘和卡片矩阵。两者可以嵌套，不需要把所有布局统一成一种技术。

### 展开说明

选择时先看内容驱动还是轨道驱动。Flex 更擅长内容尺寸与剩余空间分配，Grid 更擅长声明稳定的行列轨道。固定尺寸、最小宽度和溢出处理要一起设计，不能只写一条 `display`。

```css
.dashboard {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 16px;
}

.toolbar {
  display: flex;
  align-items: center;
  gap: 8px;
}

.toolbar__search {
  min-width: 0;
  flex: 1;
}
```

### 项目表达

后台页面的主结构常用 Grid 定义侧栏与主区域，内部工具栏和表单项用 Flex。遇到文本溢出时，我会检查 Flex 子项是否缺少 `min-width: 0`，而不是只不停加省略号样式。

### 可能追问

- 圣杯和双飞翼布局还需要吗？理解历史思路即可，现代项目优先使用 Flex 或 Grid，除非要兼容明确不支持的环境。
- `flex: 1` 到底是什么？常见等价形式是 `flex: 1 1 0%`，表示可增长、可收缩、基础尺寸为 0%。

## P0：什么是层叠上下文？为什么 `z-index` 不生效？

### 30 秒回答

`z-index` 只在相关定位或层叠上下文规则中比较，且子元素无法跨越父级所在层叠上下文与外部元素竞争层级。`position` 配合 `z-index`、`transform`、`opacity` 小于 1、`filter`、`isolation` 等都可能创建新的层叠上下文，因此排查时要看完整父链，而不是无限增大数字。

### 展开说明

弹窗被遮挡时，先检查它是否被 `overflow` 裁剪、是否处于低层级父容器、是否因为 transform 创建了隔离上下文。全局弹窗通常通过 Vue Teleport 挂到 `body` 下，再由统一层级规范管理。

```css
.dialog-layer {
  position: fixed;
  inset: 0;
  z-index: 1000;
}

.content {
  /* 不要为了动画无目的地给所有祖先加 transform */
  position: relative;
}
```

### 项目表达

我会给项目定义有限的层级 token，例如普通内容、吸顶、下拉层、弹窗、通知，而不是允许页面随意写 `z-index: 999999`。这样能减少组件组合后的层级事故。

### 可能追问

- `position: fixed` 一定相对视口吗？大多数情况下是，但某些祖先的 transform 等属性会改变它的包含块，需要实际检查。
- 为什么弹窗常用 Teleport？避开父组件的裁剪和层叠上下文，同时保留组件逻辑归属。

## P0：如何做响应式与可访问性兼顾的表单和图片？

### 30 秒回答

响应式不只是媒体查询，还包括弹性尺寸、内容溢出、触摸区域和不同输入方式。可访问性方面，表单控件要有可关联的标签和错误说明，图片根据内容决定合适的 `alt`，纯装饰图片应使用空 `alt`。不能用颜色作为唯一状态提示。

```html
<label for="email">邮箱</label>
<input id="email" aria-describedby="email-error" aria-invalid="true" />
<p id="email-error" role="alert">请输入有效邮箱</p>

<img src="chart.png" alt="近七日订单趋势图" />
<img src="divider.png" alt="" />
```

### 项目表达

我会把可访问性纳入组件验收，而不是最后补几个 `aria-*`。例如弹窗要处理焦点进入、焦点返回和 ESC 关闭；自定义按钮不能只绑定 click，还要保证键盘可操作。

### 可能追问

- `rem`、`vw`、容器查询如何选？优先从组件和内容约束出发；字体与整体比例可用 rem，视口或容器相关布局可选择对应单位或查询，避免单一单位解决所有问题。

## P1：BFC 还需要理解吗？

### 30 秒回答

BFC 是块级格式化上下文，它定义了块级盒子内部的布局规则。现代布局中更常用 Flex 和 Grid，但理解 BFC 有助于解释浮动包含、外边距折叠和某些溢出问题。不要为了触发 BFC 随意加 `overflow: hidden`，它可能裁剪内容。

```css
.flow-root {
  display: flow-root;
}
```

`display: flow-root` 的语义比为了清浮动使用隐藏溢出更明确。

## P1：CSS 性能应关注什么？

### 30 秒回答

CSS 性能通常不是选择器微优化，而是减少不必要的布局、绘制和大面积视觉更新。动画优先考虑 `transform` 与 `opacity`，但仍要在真实设备验证；大量节点和复杂阴影、滤镜也会带来成本。

### 项目表达

卡顿问题先用性能工具定位。若是大列表则考虑虚拟化，若是动画则检查每帧工作和图层数量，若是样式抖动则查看是否存在读写交错导致的同步布局。
