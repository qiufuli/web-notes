# Vue 2 核心原理与遗留项目治理

> Vue 2 经验不是需要回避的“旧技术”。真正有价值的是：你能讲清楚它为什么这样工作、边界在哪里，以及怎样在不冒险重写的前提下把存量系统维护好。

## 一、先建立一条主线：状态怎样变成页面

Vue 2 页面更新可以先用这条因果链理解：

```text
data / props 被访问
  -> getter 收集当前 Watcher
状态被修改
  -> setter 通知 Dep
  -> Watcher 进入更新队列
  -> Vue 合并本轮更新
  -> render 生成新 VNode
  -> patch 更新真实 DOM
```

这条链能解释大多数 Vue 2 面试题：为什么新增属性不响应、为什么要 `$nextTick`、为什么 `computed` 有缓存、为什么组件不能直接改 prop。

## 二、Vue 2 响应式：它为什么能知道“谁需要更新”

### P0：Vue 2 的响应式原理和边界是什么？

#### 先问一个真实问题

如果模板是：

```vue
<span>{{ user.name }}</span>
```

当 `user.name` 改变时，Vue 需要知道该重新执行哪个渲染逻辑。如果每次数据变化都刷新整棵页面，会做大量无关工作；如果完全依靠开发者手动更新 DOM，业务会很快失控。

### 1. 初始化时安装 getter/setter

Vue 2 主要通过 `Object.defineProperty` 改写初始化时已经存在的属性：

```js
let value = '首页'

Object.defineProperty(state, 'title', {
  get() {
    // 当前正在执行的渲染 Watcher 会在这里被收集
    return value
  },
  set(nextValue) {
    value = nextValue
    // 通知订阅这个属性的 Watcher
  },
})
```

可以把内部角色理解成：

```text
Dep：某个属性的订阅者集合
Watcher：组件渲染、computed 或 watch 对应的一段可重新执行工作
getter：读取时把当前 Watcher 加入 Dep
setter：修改时通知 Dep 中的 Watcher
```

### 2. 为什么新增属性和数组索引有边界

`defineProperty` 只能改写它已经知道的属性。初始化时不存在的字段，没有 getter/setter；数组索引和 `length` 也不是 Vue 2 能直接稳定拦截的普通属性。

```js
// 不可靠或不会触发预期更新
this.form.extra = 'x'
this.items[1] = nextItem
this.items.length = 0

// 使用 Vue 2 能侦测的写法
this.$set(this.form, 'extra', 'x')
this.$set(this.items, 1, nextItem)
this.items.splice(0)
```

Vue 2 会改写 `push`、`splice` 等数组方法，并在方法执行后通知更新。所以不要说“Vue 2 数组不是响应式的”，准确说法是：**部分直接写法绕过了它预先安装的侦测机制。**

### 3. 项目中的排查顺序

看到“数据变了页面没变”，先检查：

1. 字段是否在 `data` 初始化时声明。
2. 是否直接给数组索引或 `length` 赋值。
3. 是否错误地修改了 prop 或第三方对象内部字段。
4. 是否只是 DOM 尚未完成异步刷新。
5. 是否组件被 `v-if` 销毁，或者被 `keep-alive` 缓存而没有重新请求。

#### 面试回答

> Vue 2 初始化时用 `Object.defineProperty` 给已有属性安装 getter/setter。渲染或计算逻辑读取属性时，当前 Watcher 会被 Dep 收集；属性变化时 setter 通知相关 Watcher，Vue 再把组件更新合并到队列里。它的边界来自“只能侦测已存在的属性”，所以新增字段、数组索引和 length 修改需要 `$set` 或 `splice` 等方式。Vue 3 用 Proxy 从对象操作层面改善了这些问题，但依赖收集和更新调度的核心思想仍然类似。

## 三、组件状态为什么必须隔离

### P0：组件的 `data` 为什么必须是函数？

组件定义会被复用。若把可变对象直接写在组件配置中，多个实例可能共享同一个引用：

```js
// 错误示意：多个实例共享同一对象
data: {
  keyword: '',
}
```

函数则能在每次创建实例时返回一份新对象：

```js
export default {
  data() {
    return {
      keyword: '',
      page: 1,
      form: { name: '' },
    }
  },
}
```

根实例通常只创建一次，因此对象形式看起来也能工作；组件的本质要求是“每个实例拥有独立状态”。Props 的对象和数组默认值也需要工厂函数，原因相同。

## 四、computed、watch 和更新队列分别解决什么

### P0：`computed` 和 `watch` 如何选择？

先看问题类型：

```text
已有状态 -> 计算出另一个值       -> computed
状态变化 -> 发请求/写日志/同步外部 -> watch
```

```js
computed: {
  fullName() {
    return `${this.firstName} ${this.lastName}`
  },
},
watch: {
  keyword: {
    immediate: true,
    handler(value) {
      this.loadList(value)
    },
  },
},
```

`computed` 会记录依赖并缓存结果，依赖不变时多次读取不会重复计算。它应该尽量没有副作用。`watch` 的目标是执行副作用；监听大对象的 `deep: true` 会遍历更多数据，旧值和新值在原地修改时还可能指向同一引用。

### P0：Vue 的异步更新和 `$nextTick` 是什么？

如果同一段同步代码连续修改三次状态，Vue 没必要立刻 patch 三次：

```js
this.count += 1
this.count += 1
this.count += 1

this.$nextTick(() => {
  // 这一轮 Vue 更新对应的 DOM 已经刷新
  console.log(this.$refs.counter.textContent)
})
```

Vue 会把组件更新放入队列，在合适时机合并执行。`$nextTick` 等待的是 Vue 当前更新队列对应的 DOM 时机，不是等待接口、不等于随便延迟一段时间，也不等同于 `setTimeout`。

## 五、组件边界：数据应该怎样流动

### P0：Vue 2 的组件通信方式怎么选？

Vue 组件默认遵循：

```text
父组件 props 向下传值
子组件 $emit 向上表达更新意图
```

```vue
<!-- 父组件 -->
<UserEditor :value="name" @input="name = $event" />
```

子组件不应该直接修改 prop，因为 prop 的所有权在父组件。跨层但有稳定上下文时可以用 `provide/inject`；需要命令式控制焦点、校验等能力时才使用 `ref`。跨页面共享的业务状态再考虑 Vuex。

EventBus、`$parent`、`$root` 会制造隐式依赖，遗留项目里可以逐步收敛，但新代码不应优先采用。

### P0：`key` 为什么是正确性问题

列表更新时，Vue 需要判断旧节点和新节点是否是同一个身份：

```vue
<li v-for="user in users" :key="user.id">
  <input v-model="user.name" />
</li>
```

稳定、唯一的业务 ID 能让 Vue 正确复用、移动和销毁节点。使用 index 作 key 在插入、删除或排序时，可能把旧输入状态复用到错误的行。随机 key 则会让每次渲染都像创建新组件。

## 六、虚拟 DOM、生命周期和内置指令

### P1：虚拟 DOM 和 diff 怎么讲

模板会编译为 render 函数，执行后得到 VNode。状态变化时产生新的 VNode，Vue 在同层比较节点类型和 key，尽量复用或移动真实 DOM。虚拟 DOM 的价值是提供声明式更新和统一的更新模型，不是保证任何场景都比手写 DOM 快。

### P1：生命周期顺序怎样理解

不要把生命周期当成背诵表：

```text
created：实例与响应式状态已准备，DOM 还未挂载
mounted：当前组件 DOM 已挂载，可初始化依赖元素的库
updated：本次更新后的 DOM 已完成组件层面的更新
beforeDestroy / destroyed：清理监听、定时器、订阅和第三方实例
```

请求是否放 `created` 或 `mounted`，取决于是否依赖真实 DOM；真正重要的是清理由组件创建的副作用。

### P1：`v-if`、`v-show`、`v-html`

- `v-if` 控制创建和销毁，适合不频繁切换、初始可能不需要的重内容。
- `v-show` 保留节点，只切换显示状态，适合高频切换。
- `v-html` 直接写入 HTML，只能用于可信或经过净化的内容，否则可能产生 XSS。

## 七、KeepAlive、路由和状态管理要连起来

`keep-alive` 缓存的是组件实例，不是接口新鲜度。切出时触发 `deactivated`，再次进入触发 `activated`；数据是否刷新要由过期时间、版本或业务动作决定。

路由 `history` 模式需要服务端把深层路径回退到入口 HTML；导航守卫可做认证和前置权限判断，但服务端仍是最终授权边界。Vuex 适合跨页面共享且有稳定生命周期的状态，页面输入和弹窗开关不应一股脑放入全局 Store。

## 八、Vue 2 遗留项目如何治理

### P1：怎样治理长期维护的 Vue 2 项目？

不要把“全量升级”当成唯一进步方式。更稳妥的顺序是：

```text
先盘点依赖、安全和发布风险
  -> 稳定请求、错误处理和权限边界
  -> 为高频/高风险链路补测试和监控
  -> 收敛 EventBus、mixin、全局状态等隐式依赖
  -> 在低耦合模块试点 TypeScript / composable / Vue 3
  -> 用指标验证后再扩大范围
```

每次改造都要有可验证目标：减少重复逻辑、缩短问题定位时间、降低构建风险或补齐核心流程测试。不要只用“重构完成”作为结果。

## 九、面试官想听到的话

### 30 秒版本

> Vue 2 的核心链路是 getter 收集依赖、setter 通知 Watcher、更新进入队列并最终 patch DOM。它用 `Object.defineProperty` 侦测已有属性，所以新增字段、数组索引和 length 修改有边界。组件通信遵循 props 向下、emit 向上，computed 用于带缓存的派生值，watch 用于副作用，`$nextTick` 用于等待本轮 DOM 更新。维护 Vue 2 遗留项目时，我会优先稳定关键链路、收敛隐式依赖和补测试监控，再按风险和收益渐进迁移，而不是直接全量重写。

### 2 分钟版本

> 我会先从状态如何变成 DOM 讲起。Vue 2 初始化时给已有属性安装 getter/setter，渲染时读取属性会把当前 Watcher 收集到 Dep，写入时通知相关 Watcher，Vue 再把组件更新合并到队列并 patch。这个机制解释了 `$set`、数组方法、computed 缓存和 nextTick。组件边界上，父组件拥有状态，子组件通过 prop 接收、emit 表达修改意图；列表 key 提供节点身份，KeepAlive 则保留组件实例但不保证数据新鲜。遗留系统治理上，我会先处理依赖和发布风险、请求与权限边界，再为高风险链路补测试和监控，逐步替换 EventBus、mixin 和过大的 Store。这样每一步都有可验证收益，也保留回滚空间。
