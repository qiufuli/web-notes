# 求职定位与项目表达

> 十年前端经验的价值不在于报出年限，而在于能把复杂业务、稳定性、协作与技术取舍讲成可信的结果。

## P0：如何做 1 分钟自我介绍？

### 30 秒回答

自我介绍按“定位、经验主线、代表性能力、求职方向”展开，不复述简历。以 Vue 业务经验为主线，说明自己长期处理过复杂后台或业务系统、遗留项目治理和前端工程问题；同时明确正在将 Vue 2 的经验升级到 Vue 3、TypeScript、Pinia、Vite 的现代组合。

### 可使用的表达框架

> 我有多年 Web 前端开发经验，过去的项目以 Vue 2 为主，长期负责业务模块开发、公共能力沉淀和线上问题处理。我的优势是能在复杂存量系统里拆解需求、控制改动风险，并把性能、稳定性和协作规范落到项目中。最近我在系统补足 Vue 3、TypeScript、Pinia 和 Vite，关注的不只是新 API，而是如何把它们用于组件设计、状态管理和渐进式改造。我希望寻找以 Vue 为主、能够参与业务和工程质量持续改进的岗位。

### 项目表达

这段话必须换成你的真实项目类型和真实职责。不要虚构用户量、性能百分比或“主导架构重构”之类无法展开的结论。面试官通常会立刻问：你负责哪个模块、最难的问题是什么、你如何验证效果。

### 可能追问

- 为什么现在考虑变化？可以讲希望接触更现代的技术实践和更有挑战的业务，不抱怨现公司或同事。
- Vue 3 经验相对少怎么办？承认项目存量以 Vue 2 为主，同时展示已建立的知识体系、代码练习和迁移判断，而不是把它解释为“不会”。

## P0：如何把一个项目讲清楚？

### 30 秒回答

我会用“背景与约束、我的职责、关键决策、结果与复盘”来讲项目。重点只选一个自己真正深度参与的难点，说明为什么难、有哪些方案、为什么这样取舍、怎样验证结果，而不是从菜单结构开始介绍系统。

### 展开说明

一个可追问的项目故事至少需要这些事实：

1. **背景**：业务目标、用户角色、旧系统约束、交付压力。
2. **职责**：自己负责到什么边界，哪些决定由谁做。
3. **问题**：具体症状和影响，例如重复请求、首屏慢、权限错乱、发布风险、多人改同一模块。
4. **方案**：至少提及一个被放弃的方案和原因。
5. **验证**：日志、错误率、性能数据、测试、灰度反馈或人工验收。
6. **复盘**：仍有哪些限制，下次如何提前防范。

```text
背景：一个运行多年的 Vue 2 管理系统，模块耦合较高，需求频繁插入。
问题：同一业务状态分散在页面、Vuex 与缓存，修改筛选条件时容易出现旧请求覆盖新列表。
职责：我负责列表模块与请求层改造，并和后端确认接口幂等及错误码约定。
决策：先封装请求取消和请求序号校验，局部收敛状态；没有直接全量重写，因为风险和回归范围不可控。
验证：用固定复现步骤、错误监控和验收用例确认竞态消失。
复盘：后续新模块使用更清晰的状态边界，避免把页面临时状态放进全局 Store。
```

### 可能追问

- 这个结果怎么证明是你的贡献？清晰讲自己写的代码、推动的协作和可复查的验证方式。
- 方案失败过吗？可以讲真实的试错，但要说明如何止损和调整，不能把责任推给别人。

## P0：遗留 Vue 2 项目要不要直接迁移 Vue 3？

### 30 秒回答

不会因为 Vue 3 更新就直接重写。先评估业务稳定性、依赖兼容、测试覆盖、团队熟悉度和未来迭代周期。若旧系统稳定且改造收益低，优先治理可测试性、重复逻辑和构建效率；若新模块持续增加或 Vue 2 生态已形成风险，则从独立、低耦合页面开始渐进迁移，并保留可回滚路径。

### 展开说明

迁移是业务决策，不是单纯技术升级。全量重写往往在功能对齐、边界兼容、交付节奏和线上回归上付出高成本。可以先做依赖盘点、关键链路测试、组件和路由边界划分，再决定双栈共存、微前端隔离或新项目切换等策略。

### 项目表达

把“我没有迁移过”换成真实且有判断力的表达：我会先列出迁移收益、风险和前置条件，给出分阶段计划。资深工程师不一定要做过所有迁移，但应该知道什么情况下不迁移反而是正确选择。

### 可能追问

- 如何说服业务方？用风险、交付影响和可测量收益说话，避免只说“技术债”。
- 如何控制回归？关键路径自动化测试、灰度、监控、开关和回滚预案。

## P1：如何回答技术方案选型题？

### 30 秒回答

我先澄清目标和约束，再列出候选方案的关键差异，最后给出满足当前约束的选择与后续演进条件。选型不是把所有技术名词列出来，而是解释成本、风险、团队能力、性能和维护性之间的取舍。

```text
目标：多页面共享登录用户和权限，但筛选条件只在单页面使用。
判断：用户与权限可进入全局 Store；筛选条件放组件或页面级 composable。
原因：避免把短生命周期状态全局化，降低状态同步和清理成本。
演进：当筛选条件需要跨路由恢复时，再评估 URL query 或持久化方案。
```

### 可能追问

- 如何推动团队接受方案？先用小范围试点与文档降低风险，明确迁移边界和回滚条件。
- 如何处理意见不一致？回到目标和数据，记录决策理由，而不是靠资历压结论。

## P1：面试结束时可以问什么？

可以围绕岗位真正的工作内容提问：团队当前 Vue 2/Vue 3 占比、项目的发布与质量保障流程、这个岗位前三个月最需要解决的问题、技术债如何排期。避免把官网可查的问题作为主要提问。
