# 2026 面试更新层设计说明

## 目标

在现有 Docsify 笔记站中新增一套独立、可长期维护的 Vue 面试手册。新手册面向有十年前端开发经验、以 Vue 2 业务项目为主、正在补足 Vue 3 和 TypeScript 的候选人。

读者只阅读这套新手册，也应能覆盖旧资料中仍然正确且高频的内容，并获得现代 Vue 工程化、项目表达和面试追问所需的补充。内容质量优先，不以两周复习周期限制篇幅。

## 约束

- 既有 `docs/javascript`、`docs/vue`、`docs/typeScript`、`docs/htmlcss`、`docs/browerAndNetwork` 与 `interview` 中的资料保持原样，不修改内容。
- 新内容仅创建在 `docs/2026-interview/` 下；站点入口仅增加导航链接。
- 不机械复制旧资料。旧内容只有在结论仍正确、频率足够高且能服务目标岗位时才重写纳入。
- 过时、不准确或只适用于历史技术栈的结论，应删除、纠正，或在上下文中明确其适用范围。
- 语言以中文为主，保留必要的技术术语、代码和 API 名称。
- 不将 React、算法竞赛题或冷门类型体操作为主体；仅在解释迁移、工程决策或对比时简短提及。

## 内容定位

手册不作为前端百科，也不只罗列题目。每个知识点服务于以下四种场景：

1. 在面试中先给出简洁、准确的结论。
2. 被继续追问时，能够解释机制、边界和取舍。
3. 能够关联到真实 Vue 2 遗留项目、Vue 3 新项目或工程治理经验。
4. 对 Vue 3 与 TypeScript 较少的读者，能够边读边建立可落地的理解。

每个高频题使用统一格式：

```text
优先级：P0 / P1 / P2
30 秒回答
展开：原理、适用边界和常见误区
代码示例：一个独立且最小的例子
项目表达：何时采用、何时避免、如何做取舍
可能追问
```

代码示例只承担解释作用：小、完整、可独立阅读。对 Vue 3、TypeScript、Pinia 和 Vite，例子按从 Vue 2 已有认知到现代实践的顺序递进，并在例子后解释关键语句和面试表达，不把读者假定为已经熟练掌握新 API。

## 旧资料筛选与重编规则

| 旧资料主题 | 在新层中的处理 |
| --- | --- |
| JavaScript、异步、浏览器、网络、CSS | 选择高频且结论正确的部分，重新组织为面试回答与场景判断。 |
| Vue 2、Vuex、Vue Router | 保留为核心经验基础，补足边界条件，并与 Vue 3、Pinia、Vue Router 4 做明确对照。 |
| TypeScript 基础与高级类型 | 用业务建模、Vue Props、接口数据和 Store 示例重写；保留必要基础，去掉教程式重复。 |
| XHR、jQuery、HTTP 管线化、老旧兼容性技巧 | 仅作为历史对照；用 `fetch`、AbortController、HTTP/2/3、现代缓存与安全实践替代。 |
| CSS 图形、低频技巧和纯记忆型题目 | 不作为主体；只有在高频布局或项目场景中有价值时保留。 |

重新编写时要特别校正旧资料中容易误导的描述，例如：CORS 对请求和响应读取的实际限制、HTTP 持久连接与 HTTP/2/3 的关系、`watch` 深度监听、浏览器与 Node 的事件循环差异、对象去重的边界条件，以及 Vue 2 与 Vue 3 生命周期和响应式机制的适用范围。

## Vue 3、TypeScript、Pinia 与 Vite

### Vue 3

从 Vue 2 Options API 的已有概念出发，依次覆盖：响应式系统、`ref` 与 `reactive`、`computed` 与 `watch`、生命周期、`<script setup>`、Props/Emits、依赖注入、Composable、异步组件、`Teleport`、`Suspense`、性能和常见陷阱。示例需要同时说明“Vue 2 中对应什么”和“为什么 Vue 3 推荐这样写”。

### TypeScript

重点是日常业务开发：基础类型、对象与函数、联合类型和收窄、泛型、`keyof`、条件类型、常用工具类型、声明文件与第三方库类型。每个进阶类型都应在 Vue 组件、接口响应、表单、通用请求或 Pinia Store 中给出实际用途，避免为类型技巧而类型技巧。

### Pinia

覆盖 Store 设计边界、`state`/`getters`/`actions`、Setup Store、异步请求、状态持久化、跨 Store 协作、测试思路、Vuex 对比，以及 Vue 2 存量项目选择继续使用 Vuex 还是迁移 Pinia 的判断标准。

### Vite

覆盖开发服务器快的原因、依赖预构建、生产构建、环境变量、别名、代理、静态资源、代码分包、Source Map、与 webpack 的差异和迁移考虑。重点是工程决策与排障，不罗列无上下文的配置项。

## 导航与验收

完成内容创建后，在现有 Docsify 导航中增加一个清晰的 `2026 面试更新` 入口。入口只指向新手册的 `README.md`，不替换或重排旧资料链接。

验收条件：

1. 所有新页面只位于 `docs/2026-interview/`，旧资料正文没有改动。
2. 新手册入口可从 Docsify 导航访问。
3. 每个核心主题都有 P0 内容、简洁回答、解释、最小代码示例和追问或项目表达。
4. Vue 3、TypeScript、Pinia、Vite 不依赖旧页面，具备循序渐进的学习路径。
5. 新内容中的技术结论与现代浏览器、Vue 3、Pinia、Vite 主流实践一致，并明确历史技术的适用条件。
